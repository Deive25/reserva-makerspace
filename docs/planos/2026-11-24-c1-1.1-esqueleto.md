# C1 1.1: esqueleto da API (plano)

**Objetivo:** uma solução .NET 10 que compila, testa e sobe com um comando, com a primeira regra do domínio (`Intervalo`), o banco com a primeira migração, `/saude`, erros em ProblemDetails, documentação OpenAPI e CI.
**Arquitetura:** `Dominio` sem dependências; `Api` com EF Core + Npgsql; testes de unidade sem Docker e de integração contra um PostgreSQL real (Testcontainers). `Contratos` entra no 1.2 e `Web` no 1.8 (nada de projeto vazio).
**Spec:** `docs/specs/2026-11-24-c1-reserva-makerspace-design.md` (§3, §5 "Erros" e "Documentação", §6, §7, §9 linha 1.1).
**Branch:** `feat/esqueleto`, a partir da `main` (que só tem a spec e este plano).

## Restrições globais
- `net10.0`, SDK fixado em `global.json` (`10.0.403`, `rollForward: latestFeature`). Solução em `.slnx`.
- `Directory.Build.props`: `Nullable`, `ImplicitUsings` e `TreatWarningsAsErrors` ligados. Versões centralizadas em `Directory.Packages.props`, sempre a última estável (EF Core e Npgsql 10.x).
- Nenhuma senha em arquivo versionado: o `.env` fica no `.gitignore` e o `.env.example` vai sem valor de senha.
- Código, mensagens, títulos de erro, commits e docs em português. Commits sem trailer de coautoria.
- Portas no host: PostgreSQL **5433** e API **5080**, porque as do J1 (5432 e 8080) podem estar em uso.
- Testcontainers numa versão que funcione com o Docker Engine 29 (API mínima 1.44). Se der erro de versão da API do Docker, atualize o pacote, e não use variável de ambiente para contornar.

## Foco da revisão (o que nenhum critério da spec cobre, mas pega quem usa)
1. A API sobe sem a connection string → falha na subida com uma mensagem que diz qual variável configurar (`ConnectionStrings__Makerspace`), e não com `NullReferenceException`. Teste na Tarefa 2.
2. O banco cai → `/saude` responde **503** em poucos segundos, sem 500 e sem travar. Teste na Tarefa 2.
3. Horários com fusos diferentes (`-03:00` × `Z`) → o `Intervalo` compara instantes, e não o relógio local. Teste na Tarefa 1.
4. Rota inexistente → 404 em `application/problem+json`, com o título em português. Teste na Tarefa 2.
5. `docker compose up` sem `.env` ou sem senha → o Compose para com a mensagem "Defina POSTGRES_PASSWORD no .env", sem subir um banco vazio. Verificação na Tarefa 3.

### Tarefa 2: API, banco, `/saude`, erros e OpenAPI
**Arquivos:**
- `src/ReservaMakerspace.Api/` (`Program.cs` com `public partial class Program;`, `Dados/MakerspaceDbContext.cs`, `Dados/Migrations/*`, `Erros/TitulosDeErro.cs`, `appsettings.json` sem connection string);
- `.config/dotnet-tools.json` (`dotnet-ef` 10.x);
- `tests/ReservaMakerspace.Testes.Integracao/` (`FabricaDaApi.cs`, `ApiCollection.cs`, `SaudeTests.cs`, `ErrosTests.cs`, `DocumentacaoTests.cs`, `SubidaTests.cs`).

**Produz:**
- `MakerspaceDbContext : DbContext`, com `HasPostgresExtension("btree_gist")` no `OnModelCreating` e a migração `Inicial`.
- Configuração lida na subida:
  - `ConnectionStrings:Makerspace`, obrigatória. Se faltar: `InvalidOperationException` com o texto "Configure a connection string ConnectionStrings__Makerspace.";
  - `Banco:AplicarMigracoesNaSubida`, `bool`, padrão `true` (`Database.MigrateAsync()` antes do `Run`).
- `/saude`: `MapHealthChecks` + `AddDbContextCheck<MakerspaceDbContext>()`. Responde 200 `Healthy` ou 503 `Unhealthy`.
- Erros:
  - `AddProblemDetails` com `CustomizeProblemDetails`, que troca o título pelo de `TitulosDeErro`: 400 "Requisição inválida", 401 "Não autenticado", 403 "Acesso negado", 404 "Recurso não encontrado", 409 "Conflito", 422 "Regra de negócio violada", 500 "Erro interno";
  - `UseExceptionHandler()` e `UseStatusCodePages()`.
- Documentação e controllers: `AddOpenApi`/`MapOpenApi` (`/openapi/v1.json`) e `MapScalarApiReference` (`/scalar`), sempre ligados; `AddControllers`/`MapControllers`, já prontos para o 1.2.

**Testes:**
- `FabricaDaApi : WebApplicationFactory<Program>` sobe um `PostgreSqlContainer` (`postgres:17-alpine`) no `InitializeAsync` e passa a connection string por `UseSetting`. É compartilhada por `[CollectionDefinition]`.
- Os testes de subida e de banco fora do ar usam fábricas próprias, sem container.

- [ ] **Testes primeiro:**
  - `Saude_com_banco_no_ar_responde_200`: status 200, corpo `Healthy`.
  - `Migracao_inicial_cria_btree_gist`: `SELECT count(*) FROM pg_extension WHERE extname = 'btree_gist'` = 1.
  - `Rota_inexistente_responde_problem_details_em_portugues`: `GET /nao-existe` → 404, `Content-Type` `application/problem+json`, `title` "Recurso não encontrado", `status` 404.
  - `OpenApi_publicado`: `GET /openapi/v1.json` → 200 com a chave `openapi`.
  - `Scalar_publicado`: `GET /scalar` → 200 `text/html` (siga redirecionamento, se houver).
  - `Saude_sem_banco_responde_503`: connection string para `Host=127.0.0.1;Port=1;…;Timeout=2`, `Banco:AplicarMigracoesNaSubida=false` → 503 em menos de 10 s.
  - `Subida_sem_connection_string_falha_com_mensagem_clara`: sem `ConnectionStrings:Makerspace` → `InvalidOperationException` contendo `ConnectionStrings__Makerspace`.
- [ ] Implementar até `dotnet test` (solução inteira) passar com o Docker aberto.

### Tarefa 3: Docker, Compose, CI, README e ADRs
**Arquivos:** `Dockerfile` e `.dockerignore` na raiz, `docker-compose.yml`, `.env.example`, `.github/workflows/ci.yml`, `README.md`, `docs/decisoes/0001-estrutura-da-solucao.md`, `docs/decisoes/0002-migrations-na-subida-da-api.md`.

- **Dockerfile:** dois estágios (`mcr.microsoft.com/dotnet/sdk:10.0` → `aspnet:10.0`). Primeiro copia `*.props`, `global.json` e os `.csproj`, para o `restore` ficar em cache. Publica só a `Api`, roda com `USER $APP_UID` e `ASPNETCORE_HTTP_PORTS=8080`. O `.dockerignore` deixa de fora `bin/`, `obj/`, `.git/`, `.env` e `tests/`.
- **Compose:**
  - serviço `banco` (`postgres:17-alpine`, `5433:5432`, volume nomeado, *healthcheck* com `pg_isready`, `POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?Defina POSTGRES_PASSWORD no .env}`);
  - serviço `api` (build da raiz, `5080:8080`, `depends_on` com `condition: service_healthy`, `ConnectionStrings__Makerspace` montada a partir das variáveis do `.env`).
- **`.env.example`:** `POSTGRES_DB=makerspace`, `POSTGRES_USER=makerspace`, `POSTGRES_PASSWORD=` (vazio).
- **CI:** igual ao padrão do J1. `push` só na `main` e em `pull_request`, com `permissions: contents: read`. São dois jobs em paralelo no `ubuntu-latest` com `timeout-minutes: 15`:
  - `testes`: `actions/setup-dotnet@v4` com `global-json-file`, `dotnet restore`, `dotnet build -c Release --no-restore` e `dotnet test -c Release --no-build`;
  - `imagem`: `docker build .`.
- **README:**
  - o problema, em 2–3 frases da spec §1;
  - o estado do roteiro (1.1 em andamento);
  - como rodar: `cp .env.example .env`, definir a senha, `docker compose up --build`, `http://localhost:5080/saude` e `/scalar`;
  - como testar: `dotnet test`, com o Docker aberto;
  - as decisões (links para os ADRs);
  - a seção "Como foi feito", com a frase "Desenvolvido com apoio de ferramentas de IA, com as decisões e a revisão feitas por mim.".
- **ADRs** no formato do J1 (Status · Incremento · data; Contexto, Decisão, Alternativas, Consequências; até ~30 linhas cada):
  - **0001:** domínio separado, `Contratos` compartilhado com o Blazor, sem Clean Architecture completa;
  - **0002:** migrations na subida, aceitável com uma instância. Com várias instâncias, seria um *migration bundle* no deploy.
